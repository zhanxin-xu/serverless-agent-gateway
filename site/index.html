工作原理

一条消息，从进来到回出去。

每个聊天一条只追加的事件流。消息、模型输出、工具调用和结果全部入库，模型的输入从中推导。

为什么是 Serverless

不需要服务器。

部署在 Vercel Functions 上，有消息才运行，没人说话就不花钱。

0台需要维护的服务器
300s函数时限，到点自动接力
97.8%线上一轮对话的缓存命中率
¥0部署与存储费用

有消息才运行

没有常驻进程。Webhook 触发一个函数，回执之后在后台跑 agent，临近 300 秒时限自动收尾，或者带着运行锁接力给新的函数实例，中途被杀也能从事件流恢复。

部署免费

Vercel Hobby 加 Supabase、Upstash Vector 的免费版就够：Supabase 不限 API 请求次数，Vercel Sandbox 超额只会暂停、不会扣费。不用买服务器，也不用维护。

模型按用量付费

免费的是部署和存储，模型调用按用量付给 OpenRouter 等供应商。事件流只追加、前缀稳定，线上一轮对话的缓存命中率在 97% 以上，这部分开销也压得很低。

能力

像一个真的群友，
而不是一个问答框。

  1. 01

    多渠道接入

    QQ（单聊、群聊、频道，Ed25519 验签）、Telegram、通用 HTTP。所有渠道实现同一个适配器接口，新增渠道就是写一个适配器、加进组合。

  2. 02

    一个聊天一个 agent

    收消息和跑 agent 解耦。几个人同时发消息只会有一个 agent 来回答；锁是会话行上的租约，每一次写库都要确认仍持有锁。

  3. 03

    像真人一样聊天

    分几条连发、回复指定的消息、主动挂断、发表情包；在群里旁观没 @ 它的消息，自己判断要不要插话。

  4. 04

    看图、听语音

    图片缩小后入库，以前的图片也能再看；QQ 语音使用平台自带的转写文字。

  5. 05

    长期记忆

    基于 Upstash Vector 的语义检索，所有聊天共用一个记忆库，并记录每条记忆的来源。

  6. 06

    沙盒工作区

    在 Vercel Sandbox 里跑 bash、Python、Node，每个聊天有一块自己的持久盘，能读图、能把文件发回聊天。

  7. 07

    联网

    搜索和网页抓取，另有余额和额度查询工具。

  8. 08

    画图、修图

    通过 OpenRouter 或 OpenAI 的 Image API 生成图片，可以把群友发来的照片当参考图来改，结果直接发回聊天。

  9. 09

    发语音

    用固定的嗓音把文字念出来，支持用 [语气] 指挥演绎，在 QQ 里是能直接播放的语音条。

  10. 10

    四种模型协议

    通过 pi-ai 支持 OpenAI Responses、Chat Completions、Anthropic Messages、Google Gemini，默认走 OpenRouter。思维链整个回传，请求体可以按层级覆盖任意字段，比如锁定供应商、设置推理强度。

  11. 11

    上下文自动压缩

    上下文用到预算（默认 20 万 token）的 80% 时自动压缩成摘要；思维链原样回传，缓存持续命中。

  12. 12

    花费上限

    模型和画图各有每日、每月的花费上限，每个聊天还能单独设额度。只报 token 的调用按内置价目表计价，价目每天自动同步。

开始

三步跑起来。

1

部署

点击 Deploy 按钮，或者克隆仓库后在根目录运行下面的命令。项目的 Root Directory 设成 packages/vercel。

$ npx vercel
2

设密码、连数据库

在 Vercel 项目里添加环境变量 ADMIN_PASSWORD，在 Storage 页面添加 Supabase（会自动注入数据库连接），然后重新部署。

ADMIN_PASSWORD=你的管理密码
Storage → Supabase → Connect
3

打开管理端

访问 /admin，按新手引导一步步来：建表、填模型 Key、接渠道、发条消息试试。也可以访问 /api/health 检查状态。

GET /api/health
{ "store": "Supabase", "admin": true, … }

问答

常见问题。

部署 Serverless Agent Gateway 需要购买服务器吗？

不需要服务器。网关直接部署在 Vercel Functions 上，配合 Supabase 免费版存储事件流与会话锁，有消息推进来才触发运行，平时零维护、零部署与存储费用。

支持接入哪些聊天渠道和大语言模型？

内置支持 QQ（单聊、群聊、频道，支持 Ed25519 验签）、Telegram Bot 以及通用 HTTP Webhook；模型侧通过 pi-ai 支持 OpenAI Responses、OpenAI Chat Completions、Anthropic Messages、Google Gemini 四种协议，默认通过 OpenRouter 调用。

Vercel Functions 有运行时间限制，复杂的 Agent 工具调用超时怎么办？

网关采用先回执、后在 waitUntil 后台运行的机制，全部状态实时写入只追加事件流。当临近 300 秒函数时限时会自动收尾或签名接力给新的 /api/worker 函数实例，即使中途被终止也能从事件流无损恢复。

模型的花费怎么控制？

模型和画图各有每日、每月的花费上限（美元），所有聊天合计；每个聊天还能单独设每日额度。额度用完后，被 @ 时回一句额度用完了，平时不再插话。服务只报 token、不报金额的调用，按仓库自带的模型价目表计价，价目表每天自动同步。

改配置需要重新部署吗？

不需要。除了管理密码和数据库连接这两项环境变量，其余配置（模型、渠道、各模块的 Key 和参数）都在管理端里填，存进数据库，改完 30 秒内生效。也可以照旧只用环境变量配置。

能换成自己的人设吗？

可以。仓库自带的大肥鱼只是示例：人设的提示词、示例对话、表情包、形象和声音都在 packages/vercel/src/personas/ 目录里，在部署的组合 composition.ts 里换成自己的即可。每个聊天还可以在管理端里加一段只对它生效的额外设定。
