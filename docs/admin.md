# 管理端

部署后打开 `https://<域名>/admin`。管理端可以做这些事：

- 填写和修改全部配置，key 也在这里填。配置存在数据库里，改完 30 秒内生效，不用重新部署。
- 看每个聊天的聊天记录和事件流。
- 以机器人的身份发消息，或者悄悄告诉它该说什么。
- 给每个群单独设置回复方式、插话频率、能用的模块、额外设定和每日额度，并查看这个群实际发给模型的系统提示。
- 在“模块”页看机器人的每样本事：开没开、没开的原因、用的哪家服务、给模型的说明原文和工具定义。

## 需要的环境变量

| 变量 | 谁来设 | 用途 |
|---|---|---|
| `ADMIN_PASSWORD` | 你 | 登录管理端 |
| `SUPABASE_URL`、`SUPABASE_SECRET_KEY` | Vercel 的 Supabase 集成自动注入 | 运行时读写数据库 |
| `POSTGRES_URL_NON_POOLING` | Vercel 的 Supabase 集成自动注入 | 管理端一键建表和升级表结构。没有它也能用，只是要自己去 SQL Editor 执行 |

其余配置都可以在管理端里填。每项配置按这个顺序取值：**管理端（数据库）→ 同名环境变量 → 默认值**。

## 新手引导

什么都没配置时，打开 `/admin` 会先提示去 Vercel 设置 `ADMIN_PASSWORD`。这是唯一一次需要重新部署。登录以后，引导分六步：

1. **管理密码**：已经设置好了。
2. **数据库**：
   - 还没连 Supabase 时，页面给出 Vercel Storage 页面里的操作步骤。
   - 连上以后点“建表”，会执行 [`supabase/schema.sql`](../supabase/schema.sql)。
   - 以后代码需要新的表结构时，这里会显示“升级到 vN”。
3. **模型**：填写服务地址、Key 和模型。点“测试”会先保存，再真的发一次请求。
4. **接入渠道**：至少接一个。
   - QQ：页面给出回调地址，“检查”按钮会去取 access token 验证凭据。
   - Telegram：只填 token，点“保存并设置 Webhook”。页面会自动拿到机器人用户名，生成 secret，并调用 setWebhook。
   - HTTP：点“生成 Token”，新 token 只显示这一次。
5. **可选模块**（画图、语音、搜索、记忆、沙盒）：都可以跳过。每个模块只问开启需要的最少几项（各实现的 `essentials`），其余参数在配置页。
6. **发条消息试试**：收到第一条消息后自动打勾。

引导完成后，导航里会一直保留“引导与检查”入口，可以随时回来检查。

## 密钥

- key 和其他配置一样，以明文存在 `gateway.settings` 里。哪些配置算密钥由配置目录（`src/settings/catalog.ts`）决定。
- 这张表在私有 schema 里，开了行级安全（RLS），只有服务端密钥能调用读写它的函数，外部通过 Supabase 的接口读不到。
- 管理端页面只显示 key 的前几位和后四位，接口从不返回原文，操作记录里也只记 key 的名字。
- 能打开 Supabase 控制台表格编辑器的人能看到原文，所以请像保管 Vercel 账号一样保管 Supabase 账号。
- 换 `ADMIN_PASSWORD`：在 Vercel 改完重新部署，用新密码登录即可。已登录的会话会失效，已存的配置不受影响。

## 每个聊天的设置

在聊天页的“设置与额度”里改。改完 30 秒内生效。

| 项目 | 说明 |
|---|---|
| 备注名 | QQ 不提供群名，起个好认的名字 |
| 回复方式 | **正常**：被 @ 必回，平时偶尔插话。**只回 @**：不插话。**只记录**：一律不回（`/reset` 也不执行），消息留作以后的上下文。**屏蔽**：连记录都不存。没设置时用 `CHAT_DEFAULT_MODE` |
| 插话频率 | 这个群的 `AGENT_AMBIENT_INTERVAL_SECONDS` |
| 能用的模块 | 按模块开关：长期记忆、搜索、沙盒、画图、语音。关掉的模块，它的工具和说明都不会出现在这个聊天的请求里。关掉沙盒，画图也跟着关（画图依赖沙盒） |
| 额外设定 | 加在系统提示最后，只对这个聊天生效 |
| 每日额度 | 模型花费（美元）、画图张数、语音条数、搜索次数。每天北京时间 08:00（UTC 0 点）重置 |

页面底部的“看这个聊天的系统提示和工具”会列出这个聊天现在实际发给模型的系统提示，一段一段标明来源（人设、业务规则、场景、渠道、模块：长期记忆……），以及给了哪些工具。

**存储格式**：每个聊天关掉的模块存在 `gateway.chat_profiles` 的 `disabledModules` 里。

**额度用完以后**：

- 模型花费用完：被 @ 或私聊时回复一句“今天的额度用完了，几点恢复”，平时不再插话。处理方式和模型 key 没余额时一样。
- 画图、语音或搜索用完：只有那个工具会报错，模型会自己说明。

用量从事件流里统计。每一轮结束后，网关把这一轮的 token、花费和工具调用次数按 UTC 日期累加进 `gateway.usage_daily`。花费的取法：

- 优先用接口报告的金额，OpenRouter 会报告。
- 接口没报告时，用 `MODEL_PRICE_INPUT`、`MODEL_PRICE_CACHED`、`MODEL_PRICE_OUTPUT` 三个单价估算（美元 / 百万 token）。

## 模块页和配置页

- **模块页**（`#/modules`）：每个模块一张卡片，写着开没开（没开时写原因，比如“还没填 DeepSeek API Key”“需要先开启沙盒”）、背后的服务用的是哪个实现（指定的还是自动选的）、它的工具、可以设的额度。展开能看到它加进系统提示的那一段原文和工具定义。模块是什么见[模块](modules.md)。
- **配置页**：左边列表里每个可选模块一项。模块页上面是模块自己的配置，包括“用哪个实现”（留空表示自动：只有一个实现配好了就用它）；下面每个实现一张卡片，写着“在用 / 可用 / 未配置”和它自己的配置项，在用的那个实现有“检查”按钮。记忆和沙盒的数据存在服务那边，换实现后旧数据看不到。
- **总览**：每个能查余额的模块一格（模型 key、画图 key、搜索余额），加上今天每个计量模块的用量。

## 代发和悄悄话

聊天页底部的输入框有两种模式：

- **直接发出**：原样发到聊天里。
  - 事件流里记一条 `admin/message`，模型会把它当成自己说过的话。
  - 和机器人自己写的一样，`@#3B6834` 会变成真正的 @。
- **让她自己说**：写一句只有机器人能看到的指示，比如“提醒大家今晚 8 点开会”。
  - 它会被当成一条 @ 机器人的消息记下来，并立刻唤起一轮。
  - 机器人用自己的口气在聊天里回复。
  - 回复方式是“只记录”或“屏蔽”的聊天里，她不会回复，所以不能用这个模式。

**QQ 的规则**：

- 群里 5 分钟内（私聊 60 分钟内）有人说过话，就回复那条消息。
- 过了这个时间，就作为主动消息发到群里。前提是群主在群设置里开启了「机器人主动在群聊内发言」；私聊要求对方没有关闭接收主动消息。QQ 拒收时，页面会提示原因。
- 每条消息最多回复 5 次（包括主动消息），管理端发的和机器人自己回复的共用这 5 次。
- 输入框上方会显示这次发送挂在哪条消息上、还剩多少时间、还能发几条；过了时间就显示“作为主动消息发出”。

Telegram 没有这个限制。HTTP 渠道没法主动推送，所以不能代发。

## 聊天记录和事件流

两个页面读的是同一份数据：事件流（`gateway.events`）。没有另存一份聊天记录。

- **聊天记录**：从事件流里挑出“谁说了什么”，渲染成对话气泡。
  - 群友的消息来自 `user/message`。
  - 机器人发出的内容来自 `bot/sent`，包括文字、表情包、语音、文件，也包括它自己发的“没余额了”之类的提示。
  - 管理员代发的话来自 `admin/message`。
- **事件流**：只列模型读到和写出的内容（消息、系统提示、它的输出、工具结果、压缩摘要），按它读的顺序、不截断，像聊天一样最新的在下面，往上翻看更早的。每次 end_turn（或一轮以别的方式结束）为一组；一轮运行时进来、模型在它 end_turn 之后才读到的消息，归到下一组，因为那是下一轮要处理的。组标题显示触发方式、步数、token、缓存命中、花费和结束原因。点一行可以看原始 JSON。
- 两个页面能看到多早的内容，取决于事件流里还剩什么。上下文压缩会删掉旧事件（换成一段摘要），`/reset` 会清空日志，聊天 7 天没动静会被整个清理。这些被删掉的内容在两个页面里都看不到。
- 事件页还有两个按钮：
  - **重置上下文**：等同 `/reset`，会清空事件流，聊天记录也就跟着没了。
  - **释放锁**：给卡住的运行用。正在跑的那一轮会在下一次写入时停下。

## 安全

- 登录后发一个 HttpOnly、SameSite=Strict 的 cookie，7 天有效。
- 同一个 IP 15 分钟内输错 10 次密码，会被暂时拒绝登录。
- 修改类请求必须带 JSON 请求体，而且来源必须是本站。
- 页面带严格的 CSP：只加载自己的脚本和样式，不允许被嵌入其他网站。
- 所有管理操作（改设置、代发、悄悄话、重置、解锁）都记在“操作记录”里，保留 180 天。密钥只记名字。

## 代码在哪

| 位置 | 内容 |
|---|---|
| `src/settings/` | 配置目录（每项的默认值和校验）、从数据库加载和保存 |
| `src/chats/` | 每个聊天的设置、用量与额度、从事件流渲染聊天记录 |
| `src/admin/` | 管理接口（`routes/`）、登录、代发，以及页面（`ui/`，原生 JS，没有构建步骤） |
| `api/admin.ts` | 函数入口；`vercel.json` 把 `/admin` 和 `/api/admin/*` 都改写到这里 |
